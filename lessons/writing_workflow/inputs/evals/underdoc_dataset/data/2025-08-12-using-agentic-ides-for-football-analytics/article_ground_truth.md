# Using Agentic IDEs for Football Analytics

*How you can create projects coding with AI, and a brief comparison of Cursor vs. Trae*

Writing code has changed in the last a couple of years. When ChatGPT appeared in the map, using a chat window and asking GPT to create something was a new way of interacting with AI.

This definitely changes the way that code and software is created.

According to the great Andrej Karpathy, who talked about this at the AI Startup School lecture in San Francisco called “ **Software Is Changing (Again)” [1](https://ricardoheredia.substack.com/p/using-agentic-ides-for-football-analytics#footnote-1),** by comparing an old vs. new paradigmon creating software:

> **“** _We now spend more time **thinking, planning, and reviewing** code generated by LLMs than memorizing syntax and programming from scratch_”.

With time, LLMs market has risen, different AI labs have developed their own open and closed source ones. New tools have also been created to help developers improve their workflows by leveraging these models, practically embedding them inside development environments, which are known as: agentic IDEs.

#### What are Agentic IDEs?

They are development environments enhanced with AI that assists with code generation. They are also compared to Agentic CLIs (command line interfaces) like Claude Code and Gemini CLI, which can be used from both the terminal and as a chat window.

These tools offer capabilities like:

- A variety of LLMs from different providers to use.

- Capacity to index your codebase and libraries documentation

- Model Context Protocols (MCP) → open standard that connects AI models to external tools, execute actions, and read data sources, through structured interfaces with LLMs.

- Ability to edit files autonomously, providing tab completions and code suggestions.

- Help in projects from planning phase to execution phase, leveraging the use of contextual documentation to understand the nuances of the project.

- Adaptation to your workflows to help amplify your development in your own domain knowledge.

#### What are their main challenges?

For the last months I’ve been using Cursor and a couple weeks ago I started using Trae, one that looks like an affordable competitor.

These tools are intuitive at first and you can get proficient at using them them pretty quickly, especially if you come from VSCode.

But like Uncle Ben says:

> “ _**With great power comes great responsibility**_" 🕷️

Things can go sideways pretty fast if you are not on the steering wheel.

Some of the main challenges I’ve faced:

- Understanding how the different LLMs work, and which one excels at which task.

- Rate limit: tracking how much of your monthly quota are you consuming. This helps you understand how to prompt better to achieve results in less iterations.

- Testing different prompt formats, to see what helps to achieve better results with each model.

- Knowing how to leverage the context window of each model.

- Keeping the leash tight in Agent mode, trying not to let it go rogue and make extreme codebase changes without supervision.

- Integrating MCPs using them as extra tools that improves my workflow. Especially the ones that are suitable for my project.

You’'ll see how to tackle these challenges with a framework I used and how I applied it in two football-related use cases.

#### How can you leverage them for Football Analytics?

One of the things I like the most about AI is that it is here to augment our capabilities and help us create opportunities within our domain knowledge.

In this case, I followed a general framework that you can replicate for any project, it works for both Cursor and Trae.

1. As soon as you open your project, create **three** files:

1. **rules.mdc**: this one sets the context of the rules [2](https://ricardoheredia.substack.com/p/using-agentic-ides-for-football-analytics#footnote-2) that the agent must follow in each project when generating code. In any conversation, it will consider anything you want your project to have: role the AI must adopt, your Python version, the libraries you use, your coding style, design pattern, etc.

2. **project\_context.md**: you’ll entire context, this is the document where you set your project’s main idea goal, characteristics of the project, steps to achieve it, anything. It’s an opportunity to describe clearly and concisely what you’re working on.

3. **tasks.m** d: granular description of your project tasks. You can use it as a log so models understand what you’ve done and your progress.

2. **Version Control** initiating **Git** from the beginning of the project: commit changes before accepting the code suggestions from the Agent, if you’re satisfied then test and proceed.

3. **Index** only necessary folders, files, and libraries documentations at the beginning, this will help the Agent pay attention to your codebase structure and understand the last version of the documentation you’re using, for example the last version of Pandas or Matplotlib.

In summary:

Open Project → create rules.mdc + project context file + initial tasks → version control → index codebase and documentation

#### Football Examples

##### Example 1: six‑plot match dashboard

For this I needed to do a bunch of stuff:

- Scraping match event data from different sources.

- Cleaning and unifying pitch coordinates and IDs

- Precalculating the metrics

- Generate the plotting functions.

You can refer the last article so see what the project is about: [Building Your Own Football Analytics Dashboards With Free Data](https://ricardoheredia.substack.com/p/building-your-own-football-analytics)

And I needed to go over each step with a structure.

1. Files

1. **rules.mdc**: emphasized the generation of the code in functions and simplified code, sometimes LLMs go way over their head and make up stuff.

2. **project\_context.md:** I went from broad to specific explanation of my project. Main goa, key components, steps to create it, plots characteristics, color and aesthetic I wanted to implement.

3. **project\_log2025.md:** this is the task document where I only set the specific task to accomplish and next steps.

2. **Version control with Git**

3. **Index files and folders:** in Trae, the context indexes automatically, in Cursor you need to indicating it at the beginning but then files are automatically synced.

From this point onwards, is a back and forth iteration, tweaking the documents, and adapting the prompts to obtain satisfactory outputs from the LLMs.

Some of the **challenges**: the model confused coordinate systems (0–100 vs 120×80), misnamed some columns, or repeated different Matplotlib functions. Had to pass the dimensions explicitly in a document to be used as context.

##### Example 2: on‑ball sequences with GPT‑5 in Cursor (Trae didn’t have it yet)

Sequence helps you not only analyze what happened in a match (player passed a ball in a specific direction and zone of the field) but also ‘ **how**’ it happened **before** and **after** that, it adds context.

I asked GPT‑5 to find sequences based on my data from Salzburg vs. Real Madrid in the CWC, and gave it freedom to pick any event and any player. I did it in 3 steps:

- Asked it to adopt the role of a PhD Level Football Machine Learning Engineer and that it needed to understand my codebase and recent progress.

- Indexed my event data, so it could understand the type of events and specifications of the plots colors.

- I asked it to plot coordinates X and Y of any event and any player.

It chose a pass where Dean Huijsen receives deep on the left in his own half and carries into the attacking half on the same flank.

Then plotted two examples with a dark mplsoccer theme and label the player.

It filtered events, computed distance gained (about 39–43m in two cases), and drew the trajectory of the sequence.

The **takeaway**: when your instruction is specific and concrete, agentic IDEs translate it into working code quickly.

#### How to get reliable results from the models

- Be specific with inputs: a well-described tasks, specific code format (generate functions).

- Paste snippets of your information (e.g. rows of your data frame) and state plotting specifications.

- Index your context: point the Agent to the exact files or docs you want it to use.

- Have it explain the logic in plain language before you run anything.

#### Quick comparison between Cursor vs Trae based on my experience

##### Cursor

Is one of the most populars, I personally find these specs useful:

- Agent mode in Claude Sonnet 4: best model I’ve tested inside Cursor, it provides well structured code and understands the codebase when you give it the entire context.

- MCP integration: most of the MCPs have integration for Cursor, for example setting Supabase was easier here than in Trae which is newer.

- Haven’t tried but looks interesting: Background Agents → edit and run code in a remote environment.

- Broader range of models: for small tasks the Cursor small own model helped me for writing specifications for project and I also liked using Deepseek v3.1 for coding, it was pretty solid.

- Something I didn’t like: the rate limit. With pro plan ($20 a month), you were suppose to have unlimited requests but one day they changed it quietly and people started to hit rate limits all of a sudden.

##### Trae

- Is cheaper: first month $3, next bill $10.

- Has two modes:

  - Builder: to execute routine and end-to-end tasks.

  - Builder with MCP: use MCP servers to run tasks.
- MCP: setting them is easier than in Cursor and they have a marketplace where you can grab and the ones you need.

- Haven’t tried but looks interesting: Custom Agent → use MCP tools and built-in ones from Trae to use a specific Agent for specific tasks.

- Needs more popularity but they are clear with the limits you have 600 a month.

- Something I didn’t like: they have a SOLO builder mode which is more autonomous and you can see the development of your app during the whole process: backend and frontend, but you have to join a waitlist to get an invitation codes that hasn’t arrived yet.

To help you evaluate them deeply you can check these two sources to help you decide:

#### Final thoughts

Agentic IDEs can help you move fast from any question you have to working code.

Start small: aim for iteration and then repeatable workflows. Keep guardrails in place: index your documents, do sanity‑checks after every iteration, have the IDE generate simple tests, and ask models to state assumptions before coding.

As you polish prompts and set rules, you’ll see the improvements.

Open Project → create rules.mdc + project context file + initial tasks → version control → index codebase and documentation
